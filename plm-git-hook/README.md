# PLM 대시보드 — Git 커밋 훅 연동

커밋 메시지에 과제 ID를 포함하면 PLM 대시보드의 진행률/상태가 자동으로
갱신됩니다. **오늘부터 바로 적용 가능**하도록 구현·테스트를 마쳤습니다.

## 적용 방법 (추적하고 싶은 저장소마다)

1. 이 폴더의 `.githooks/`, `scripts/`, `setup-hooks.sh`를 대상 Git 저장소
   루트에 복사합니다. (plm-dashboard 자체를 추적하고 싶다면 그 저장소에,
   다른 프로젝트 코드를 추적하고 싶다면 그 저장소에 복사)
2. 저장소 루트에서 실행:
   ```bash
   bash setup-hooks.sh
   ```
   `git config core.hooksPath .githooks` 를 설정해 훅을 활성화합니다.
3. PLM 대시보드 서버(`node server.js`)가 실행 중이어야 합니다. 대시보드가
   다른 호스트에 있다면 `PLM_HOST=http://<주소>:4000` 환경변수로 지정하세요.

## 커밋 메시지 규칙

| 표기 | 동작 |
|---|---|
| `#<taskId>` | 필수. 어떤 과제와 관련된 커밋인지 표시 |
| `%<0-100>` | 진행률 지정 (예: `%60`) → 상태도 자동으로 "진행중"으로 전환 |
| `완료` 또는 `done` | 과제를 완료(100%) 처리. `%`보다 우선 적용 |
| 위 표기 없이 `#<taskId>`만 | 상태만 "진행중"으로 전환 (진행률은 유지) |
| `#<taskId>` 자체가 없음 | 아무 동작 없음 (일반 커밋) |

예시:
```bash
git commit -m "훅 파싱 로직 구현 #seed-t3 %60"
git commit -m "동작 검증 완료 #seed-t3 완료"
git commit -m "리팩터링 (관련 과제 없음)"   # 무시됨
```

과제 ID는 대시보드 좌측에서 확인하거나, VS Code Tasks의
**"PLM: 과제 목록 보기"** 로 조회할 수 있습니다.

## 안전성

- **post-commit** 훅이므로 실행에 실패해도 커밋 자체는 절대 막히지 않습니다.
- PLM 서버가 꺼져 있으면 curl 호출이 조용히 실패하고 넘어갑니다(무한 대기 없음).
- 태스크 ID가 대시보드에 없는 값이어도 서버가 404를 반환할 뿐, 커밋에는
  영향이 없습니다.

## 검증 결과 (자동 테스트 완료)

임시 저장소와 임시 서버로 3가지 케이스를 확인했습니다.

1. `#taskId %60` 커밋 → 진행률 60%, 상태 "진행중"으로 정상 반영
2. `#taskId 완료` 커밋 → 상태 "완료", 진행률 100%로 정상 반영
3. 태스크 언급 없는 일반 커밋 → 과제 데이터 변화 없음 (정상)

## 세부 Task를 대시보드에 등록하려면

이번 작업의 세부 Task 6개(규칙 정의, 훅 스크립트, 설치 스크립트, 통합
테스트, 실사용 검증, 문서화)를 실행 중인 대시보드에 바로 넣고 싶다면:

```bash
PLM_HOST=http://localhost:4000 bash seed-git-hook-tasks.sh
```

앞의 4개는 오늘 완료 처리되어 등록되고, "실사용 검증"과 "문서화"는
다음 1주일간 진행할 과제로 hold 상태로 등록됩니다.
